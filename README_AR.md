# معرض الإبداع الفني ثلاثي الأبعاد

**المدرسة المتوسطة الثامنة بينبع البحر**

نسخة برمجية قابلة للتشغيل والتطوير، باستخدام React + Vite + Three.js + React Three Fiber + Supabase. كل المجسمات المعمارية مولّدة داخل المتصفح (ليست صور خلفية ثنائية الأبعاد). يوجد مبنى خارجي وبهو رئيسي و7 أجنحة × 4 قاعات = 28 قاعة، لكل منها مسار مستقل. الفن التجريدي والزخارف هندسة للديكور فقط، **وليست أعمال طالبات**.

> مهم: هذه حزمة أولى جاهزة للتشغيل وليست تأكيدًا أن خدمة Supabase أو النشر أو بيانات الطالبات أُعدّت بالفعل. العمل الحقيقي المشترك يبدأ فقط بعد ضبط الحساب والأمان واختباره. التصميم يعتمد على مجسمات هندسية وخامات، وقد يحتاج تطويرًا فنيًا إضافيًا للحصول على واقعية فوتوغرافية كاملة.

## أولاً — رفع الحزمة إلى GitHub Codespaces (من المتصفح)

1. نزّلي ملف ZIP الذي تسلّمتِه من ChatGPT إلى جهاز Windows.
2. افتحي `school-art-gallery` في GitHub Codespaces.
3. في Explorer على اليمين/اليسار حسب اتجاه الواجهة، اسحبي ملف ZIP من Downloads وأفلتيه على مجلد `school-art-gallery` نفسه. إذا طُلب التأكيد على التحميل فوافقي.
4. من Terminal أدخلي `unzip -o school-art-gallery-package.zip` ثم Enter. هذا يضع ملفات الحزمة مباشرة في جذر المشروع ويستبدل ملفات القالب. لا يوجد مجلد إضافي داخل ZIP. **مهم:** إذا كان المشروع الحالي يحوي أعمالاً خاصة بك، احتفظي بنسخة احتياطية قبل الفك.
5. أدخلي `npm install` ثم `npm run dev -- --host 0.0.0.0` (سنعطي الأوامر لكِ خطوة بخطوة خلال المحادثة).
6. في إشعار Codespaces اختاري Open in Browser لفتح رابط المنفذ 5173. إذا لم يظهر: افتحي تبويب **PORTS** بجانب Terminal ثم اختاري **Open in Browser** بجوار 5173.
7. ابدئي من الواجهة الخارجية، ثم البهو، ثم فصل 2/1، ثم الرسم، ثم جرّبي فصل 2/7 وقاعة الخزف. للتجول: اسحبي المشهد للتدوير، عجلة الفأرة للتقريب، ومفاتيح WASD للتنقل. للهواتف توجد أزرار حركة أعلى يسار أسفل المشهد.

## ثانيًا — اختبار المشروع محليًا

- `npm run build` للتأكد من نجاح البناء الإنتاجي.
- `npm run lint` للتحقق من قواعد JavaScript/React.
- `npm test` لاختبار توليد 28 قاعة وربط الفصول والأقسام.
- تأكدي أن الأزرار تنتقل بالفعل إلى المشاهد المطلوبة وأن القاعات الـ28 مستقلة.
- راقبي الأخطاء في DevTools Console، والتحميل من نافذة Network. لا تفترضي نجاحها قبل الاختبار.

## ثالثًا — تفعيل Supabase (فقط بعد التأكد من عرض المشاهد)

1. افتحي https://supabase.com وأنشئي حسابًا ومشروعًا جديدًا. احتفظي بكلمة مرور قاعدة البيانات خارج الكود. سجّلي المنطقة المناسبة لكِ. 
2. من مشروع Supabase > SQL Editor > New query، افتحي `supabase/schema.sql` من Codespaces، وانسخي محتواه **بعد مراجعته** إلى SQL Editor ثم اختاري Run. سينشئ جدول `artworks` وجدول `admin_users` وتخزينًا عامًا للصور مع سياسات RLS. لأن الصور والبيانات المعروضة عامة، لا ترفعي أي محتوى دون موافقات المدرسة والطالبات/أولياء الأمور حسب السياسات المطبقة.
3. من Supabase > Authentication > Users أضيفي مستخدمة إدارية بالبريد الإلكتروني وكلمة مرور قوية؛ يمكنك استخدام Invite user (وتأكيد الدعوة) أو Add user إن كان متاحًا. **عطّلي التسجيل المفتوح** إذا لم تحتاجيه. لا تعطي المستخدمين العاديين صلاحية الإدارة.
4. من SQL Editor نفذي الاستعلام التالي مع استبدال البريد ببريد المستخدمة الإدارية (بدون مشاركة كلمة المرور):

```sql
insert into public.admin_users(user_id)
select id from auth.users where email = 'your-admin@example.com'
on conflict do nothing;
```

5. من Project Settings > API أو Settings > Data API (بحسب واجهة Supabase)، انسخي **Project URL** و **publishable/anon key** (المخصص للاستخدام العام في واجهات المستخدم). **لا تستخدمِي `service_role` أو `secret` key في الموقع مطلقًا**.
6. داخل Codespaces من Explorer أنشئي ملفًا جديدًا باسم `.env.local` في جذر المشروع، واكتبي:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

7. أوقفي خادم Vite (Ctrl+C في Terminal)، ثم أعيدي تشغيله `npm run dev -- --host 0.0.0.0`؛ لن يقرأ التغييرات في env حتى يعاد التشغيل.
8. افتحي إدارة المعرض، سجّلي الدخول بالبريد الإداري، جرّبي رفع صورة **مصرّح بنشرها**، ثم تأكدي أن العمل يظهر في الفصل والقسم الصحيحين من متصفح آخر، وأعيدي تحميل الصفحة لاختبار استمراره. اختبري التعديل والحذف. لا يعني نجاح تسجيل الدخول وحده أنك مسؤولة؛ يجب أن تكوني في admin_users.
9. راجعي أن حسابًا غير إداري لا يستطيع الإدخال/التعديل/الحذف حتى عبر API (بفضل RLS). إذا ظهرت رسائل صلاحيات، صوّري الخطأ لنشخص إعداد السياسة.

**تنبيه:** المفتاح العام في متغير `VITE_` يُضمّن داخل ملفات JavaScript المنشورة؛ هذا طبيعي للمفتاح المخصص للواجهة العامة فقط. لا تضعي فيه مفاتيح سرية. الصورة المحذوفة تُحذف من قاعدة البيانات والتخزين وفق سياسات الإدارة؛ في حالات فشل حذف الملف قد تحتاجين حذف ملف يتيم من Storage يدويًا.

## رابعًا — النشر عبر GitHub Pages

1. احفظي الملفات بعد فك الضغط وأرسليها إلى المستودع باستخدام Source Control: من الشريط الجانبي أيقونة Branch، ثم اكتبي رسالة Commit ثم Commit وSync Changes. لا ترفعي `.env.local`؛ فهو محجوب بواسطة `.gitignore`.
2. في مستودع GitHub > Settings > Pages اختاري **Source: GitHub Actions**.
3. من Settings > Secrets and variables > Actions > Variables أضيفي: `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إذا كنتِ قد أكملتِ Supabase. هذه القيم عامة مخصصة لواجهة المستخدم ولا تُعامل كأسرار. إذا لم تضبطيها سيعمل الموقع ثلاثي الأبعاد من دون لوحة رفع سحابية.
4. انتقلي إلى Actions > Publish Art Gallery وتحققي أن Workflow أنهى build وdeploy بنجاح. إذا لم يبدأ، يمكنك تشغيل **Run workflow** عند فتحه.
5. افتحي رابط Pages الفعلي من Settings > Pages وجربي الانتقال بين المشاهد، ثم حدّثي صفحة داخل المعرض، وتحققي من عمل الصور ومفاتيح الإدارة. الاستضافة العامة قد تستغرق دقائق لتفعيل الرابط.
6. لأن `base: './'`، تعمل ملفات CSS/JS داخل مسار مستودع GitHub Pages بدون افتراض اسم حساب GitHub. لا نستخدم مسارات React Router الداخلية هنا.

## نقاط مهمة

- الواجهات لا تتطلب أن تعيدي كتابة 28 قاعة: توليدها في `src/data.js` والتصميم في `src/World.jsx`.
- لا توجد أسماء طالبات وهمية؛ جدران القاعات الفارغة تحمل توضيحًا، والزخارف هندسية للتصميم فقط.
- مستوى الجودة البصرية هنا بداية منسقة من مجسمات إجرائية، ويمكن تطوير الخامات والـ3D assets لاحقًا. هذا لا يعني محاكاة فوتوغرافية لمتحف حقيقي.
- تحتاجين إلى حساب GitHub وحصة Codespaces، وإلى حساب Supabase فقط إذا أردتِ إدارة سحابية متعددة الأجهزة.
